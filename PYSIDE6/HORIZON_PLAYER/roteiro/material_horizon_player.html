01Os três arquivos e como se relacionam

Um projeto Qt Designer + PySide6 típico tem sempre essa mesma engrenagem de três peças:

interface.ui (XML — desenhado visualmente no Qt Designer) │ │ pyside6-uic (compilador) ▼ interface_ui.py (Python GERADO — classe Ui_MainWindow) │ │ importado por ▼ main.py (código escrito à mão — classe HorizonPlayer)

interface.ui é o arquivo XML que o Qt Designer salva quando você arrasta botões, listas e sliders na tela. Ele não tem lógica nenhuma, só descreve a geometria e os nomes (objectName) de cada widget.

interface_ui.py é gerado automaticamente a partir do .ui pelo compilador pyside6-uic. O próprio cabeçalho do arquivo avisa: "WARNING! All changes made in this file will be lost when recompiling UI file!" — ou seja, é um arquivo descartável e regenerável. Nunca se edita esse arquivo na mão; qualquer ajuste de interface deve ser feito de volta no Designer (ou, em projetos mais avançados, via QSS/código em cima dele).

main.py é o único arquivo com lógica de negócio: é onde vive a classe HorizonPlayer, que sabe tocar música, montar playlist, reagir a cliques etc. Ele importa a classe gerada e a usa — é aqui que mora toda a resposta da próxima seção.

02Composição vs. herança — é uma superclasse?

Essa é a pergunta mais importante do material, porque é fácil confundir os dois padrões possíveis. A resposta curta: não, Ui_MainWindow não é superclasse de HorizonPlayer. O que existe aqui é composição (uma relação "tem-um"), não herança (uma relação "é-um").

Repare na declaração da classe:

class HorizonPlayer(QMainWindow):

HorizonPlayer herda só de QMainWindow. Ui_MainWindow nem aparece na lista de heranças. Em vez disso, dentro do __init__:

self.ui = Ui_MainWindow()   # cria um OBJETO separado
self.ui.setupUi(self)      # injeta os widgets dentro da janela

O truque está no método setupUi(self). Dentro de interface_ui.py, cada widget é criado assim:

def setupUi(self, MainWindow):
    self.centralwidget = QWidget(MainWindow)
    self.label_musica  = QLabel(self.centralwidget)
    self.btn_abrir      = QPushButton(self.centralwidget)
    # ...
    MainWindow.setCentralWidget(self.centralwidget)

Note que, dentro desse método, self é a instância de Ui_MainWindow — não a janela. Então self.btn_abrir vira um atributo do objeto Ui_MainWindow. O parâmetro MainWindow (que é o self do HorizonPlayer, passado lá do main.py) só é usado para "plugar" o widget central e a barra de menu na janela de verdade — ele nunca ganha os botões como atributos diretos.

É por isso que, em qualquer lugar do main.py, você acessa um widget como self.ui.btn_abrir, e não self.btn_abrir: o caminho de acesso passa sempre pelo objeto intermediário self.ui.

Existe a alternativa por herança

O próprio Qt/PySide6 permite outro padrão, por herança múltipla, que você provavelmente vai ver em outros tutoriais:

class HorizonPlayer(QMainWindow, Ui_MainWindow):
    def __init__(self):
        super().__init__()
        self.setupUi(self)  # aqui sim, self.btn_abrir existiria direto

Nesse segundo modelo, Ui_MainWindow seria de fato uma superclasse, e os widgets virariam atributos diretos de self (sem o .ui no meio). Funciona, mas mistura a classe "de negócio" com a classe "gerada", o que dificulta separar o que é seu código do que é gerado. O Horizon Player usa o primeiro padrão (composição), que é o mais recomendado hoje em dia justamente por manter essa separação limpa.

Em resumo, para "buscar" qualquer elemento desenhado no Designer, o caminho mental é sempre:

objeto da janela → .ui → .nome_do_objeto

E esse nome_do_objeto é exatamente o texto que você digitou na propriedade objectName lá no Qt Designer — é isso que vira o nome do atributo Python (você pode conferir em interface_ui.py, em linhas como self.btn_abrir.setObjectName(u"btn_abrir")).

03O que acontece dentro do __init__

Na ordem em que o código executa quando a janela é criada:

PassoO que faz
self.ui = Ui_MainWindow(); self.ui.setupUi(self)Monta toda a interface visual dentro da janela (ver seção 2).
self.playlist = [] / self.indice_atual = -1Estruturas de dados próprias do main.py — não existem no Designer, são o "cérebro" da playlist.
QMediaPlayer + QAudioOutputO motor de reprodução, totalmente separado da interface. QMediaPlayer controla o estado (tocar/pausar); QAudioOutput controla o volume/saída física de som.
_configurar_icones()Usa ícones nativos do sistema operacional (QStyle.SP_*) em vez de imagens próprias — deixa o app consistente com o SO sem precisar de arquivos de ícone.
_conectar_sinais()Liga todos os eventos (cliques, arrastar slider) às funções que devem reagir a eles.

04Sinais e slots — o sistema nervoso do app

Qt funciona por eventos: um widget emite um sinal quando algo acontece (clique, arrastar, terminar de carregar), e você conecta esse sinal a uma função (o slot) que deve rodar em resposta. É exatamente isso que _conectar_sinais() faz — e repare que a comunicação acontece nos dois sentidos:

Sinal (emissor)Slot (reage)Sentido
btn_abrir.clickedabrir_arquivos()Interface → lógica
btn_play.clickedplayer.playInterface → player
lista_musicas.itemDoubleClickedtocar_musica_selecionada()Interface → lógica
slider_volume.valueChangedlambda v: audio_output.setVolume(...)Interface → player
player.positionChangedatualizar_posicao()Player → interface
player.durationChangedatualizar_duracao()Player → interface
player.mediaStatusChangedverificar_fim_da_faixa()Player → lógica (autoavançar)

As três últimas linhas são as mais importantes de entender: o QMediaPlayer também emite sinais próprios (ele está tocando em segundo plano, avançando posição a cada fração de segundo), e é isso que mantém o slider de progresso e os rótulos de tempo sincronizados sem que você precise ficar checando manualmente em loop.

05O ciclo de vida de uma música tocando

  1. abrir_arquivos() — abre o QFileDialog nativo, filtra por extensões de áudio, e para cada arquivo escolhido guarda {"nome", "caminho"} em self.playlist e adiciona a linha visual na QListWidget.
  2. Se nada estava tocando ainda, chama carregar_e_tocar(0) automaticamente.
  3. carregar_e_tocar(indice) é o método central: define a fonte de áudio (QUrl.fromLocalFile), atualiza o rótulo, destaca a linha correspondente na lista e manda tocar.
  4. Enquanto toca, atualizar_posicao/atualizar_duracao mantêm o slider e os rótulos MM:SS em dia — com uma checagem (isSliderDown()) para não "brigar" com o mouse do usuário quando ele está arrastando o slider manualmente.
  5. Quando a faixa termina, verificar_fim_da_faixa() detecta o status EndOfMedia e chama carregar_e_tocar() de novo com o próximo índice — é assim que a playlist "anda sozinha".

06As duas modificações pedidas

Ambas estão detalhadas como comentários dentro do arquivo main_comentado.py (em anexo), exatamente ao lado dos métodos que elas afetam, para não misturar explicação com código funcional.

Transformar avançar/retroceder em próxima/anterior faixa

A ideia central: avancar_10s/retroceder_10s hoje fazem seek de tempo (player.position() ± 10_000) dentro da mesma faixa. Para virar navegação de faixa, basta trocar essa conta por movimentação do self.indice_atual e delegar para carregar_e_tocar(), que já sabe trocar a fonte, atualizar o rótulo e destacar a linha — nada disso precisa ser duplicado.

Deletar música(s) da lista com a tecla Delete

Toda QWidget (logo, toda QMainWindow) já recebe eventos de teclado via keyPressEvent(self, event). Basta sobrescrever esse método na classe HorizonPlayer, checar event.key() == Qt.Key_Delete, pegar a(s) linha(s) selecionada(s), remover com takeItem() (da lista visual) e del self.playlist[linha] (da estrutura de dados) — com o cuidado extra de reajustar self.indice_atual caso a música removida seja a que está tocando ou esteja antes dela na lista.

Selecionar tudo (Ctrl+A) e apagar em lote

Para ir além de "uma música por vez", duas peças precisam se encaixar:

  • Permitir seleção múltipla: por padrão o QListWidget só seleciona um item por vez. É preciso trocar o modo de seleção uma única vez, com lista_musicas.setSelectionMode(QAbstractItemView.ExtendedSelection), para habilitar Ctrl+clique, Shift+clique e a seleção total.
  • Selecionar tudo: QListWidget herda de QAbstractItemView, que já vem com o método selectAll() pronto — não é preciso reimplementar nada, só chamar lista_musicas.selectAll() quando o atalho Ctrl+A for detectado (event.key() == Qt.Key_A and event.modifiers() == Qt.ControlModifier).

Com isso, o Delete passa a apagar todas as linhas selecionadas de uma vez, não só uma. O detalhe técnico que evita bugs aqui é a ordem de remoção: as linhas selecionadas precisam ser processadas em ordem decrescente (da última para a primeira). Se removêssemos da primeira para a última, cada remoção deslocaria os índices das linhas seguintes ainda por remover, fazendo o código apagar a música errada. Removendo de trás para frente, os índices das linhas anteriores nunca mudam durante o laço.

07Seletores QSS: funcionam como CSS?

Em grande parte, sim — QSS (Qt Style Sheets) foi desenhado deliberadamente para parecer familiar a quem já conhece CSS2, e a maioria dos seletores tem equivalente direto:

SeletorExemploEquivalente em CSS
Por tipo de widgetQPushButton { ... }button { ... }
Por objectName (ID)#btn_play { ... }#btn_play { ... }
Por propriedade dinâmicaQPushButton[tocando="true"] { ... }button[data-x="y"]
Pseudo-estadosQPushButton:hover, :pressed, :disabled, :checked:hover, :active, :disabled
Sub-controles (partes internas de um widget composto)QSlider::handle, QSlider::groove::before, ::part()
DescendentesQListWidget::itemul li
A diferença que mais pega alunos de surpresa

O QSS implementa apenas um subconjunto do CSS2 e não tem @keyframes, nem a propriedade transition, nem animation. Uma folha de estilos QSS é sempre estática: ela define a aparência (cores, bordas, espaçamento, estado hover/pressed), mas não consegue, sozinha, fazer nada mudar de valor ao longo do tempo. Qualquer coisa que "se mexe" precisa vir de código Python (um QTimer, uma QPropertyAnimation, ou simplesmente trocar um valor e chamar repaint()).

08Visualização animada tipo equalizador — é possível com QSS?

Direto ao ponto: não só com QSS. QSS por si só nunca vai fazer barras "dançarem" sozinhas, porque — como vimos acima — ele não tem conceito de animação nem de valor variável no tempo. O que o QSS pode fazer é cuidar da aparência estática de cada barra (cor em gradiente, cantos arredondados, cor diferente quando "ativa"); quem faz a barra mudar de altura a cada instante é sempre código Python, geralmente um QTimer chamando um método a cada 30–50ms para atualizar valores.

O obstáculo técnico real: de onde vêm os dados do áudio?

A parte difícil não é desenhar as barras — é conseguir a amplitude/frequência real do som em cada instante para saber quão alta cada barra deve ficar. E aqui existe uma limitação importante do PySide6/Qt 6 atual: a classe QMediaPlayer + QAudioOutput (usada no Horizon Player) não expõe as amostras de áudio brutas enquanto toca. O recurso que fazia isso no Qt 5 (QAudioProbe) foi removido no módulo QtMultimedia do Qt 6.

Isso não inviabiliza o projeto — só significa escolher uma entre três estratégias:

Estratégia A — envelope pré-calculado (mais simples para uma turma)

  1. Quando uma música é carregada, ler o arquivo de áudio fora do QMediaPlayer, com uma biblioteca própria de processamento (ex.: numpy + soundfile), e calcular de antemão um "envelope" de volume (RMS) em janelas curtas, por exemplo a cada 50ms.
  2. Um QTimer roda enquanto a música toca e, a cada tique, consulta self.player.position() para saber "em que ponto da música estamos agora" e busca o valor de amplitude correspondente nesse envelope pré-calculado.
  3. Esse valor (ou uma pequena variação randomizada em torno dele, para simular várias barras de frequência) é usado para ajustar a altura de N widgets simples (podem ser QProgressBar verticais, sem texto, estilizados via QSS para parecerem barrinhas de equalizador).

Essa abordagem funciona muito bem em sala de aula: é sincronizada de verdade com a música (porque usa a posição real do player), não exige trocar o motor de reprodução, e não depende de nenhum recurso removido do Qt 6.

Estratégia B — motor de áudio próprio (visualização ao vivo de verdade)

Para ter um espectro realmente calculado em tempo real (FFT ao vivo, como um equalizador de estúdio), seria necessário trocar o QMediaPlayer por uma biblioteca de baixo nível como sounddevice ou pyaudio, que entrega o buffer de áudio bruto conforme ele é reproduzido. Aí sim dá para rodar uma FFT (com numpy) a cada callback e atualizar as barras com dados 100% ao vivo. É mais poderoso, mas troca a arquitetura de reprodução usada hoje — não é um ajuste pontual.

Existe alguma biblioteca pronta de visualização?

O PySide6/QtMultimedia não traz nenhum widget pronto de espectro/equalizador. As opções do ecossistema Python que ajudam na parte gráfica (não na captura de áudio) são:

  • pyqtgraph — biblioteca de gráficos rápidos integrada nativamente com Qt/PySide6; tem BarGraphItem pronto e é a opção mais indicada para atualizar muitos valores por segundo sem travar a interface.
  • matplotlib embutido via FigureCanvasQTAgg — mais pesado e mais lento para redesenhar a cada 30ms, melhor para gráficos estáticos do que para animação contínua.
  • DIY com QWidget + paintEvent — desenhar os retângulos manualmente com QPainter; dá mais trabalho, mas ensina bem o conceito de desenho customizado no Qt e é leve o suficiente para uma turma implementar do zero.
Esqueleto de implementação (Estratégia A) 
# pseudocódigo — não faz parte do main.py, é só ilustrativo
self.timer_equalizador = QTimer(self)
self.timer_equalizador.setInterval(50)  # 20 atualizações por segundo
self.timer_equalizador.timeout.connect(self.atualizar_barras)
self.timer_equalizador.start()

def atualizar_barras(self):
    posicao_atual = self.player.position()
    volume_no_instante = self.envelope.consultar(posicao_atual)
    # distribui o valor entre as N barras (QProgressBar verticais,
    # estilizadas via QSS) com pequenas variações por barra
    for barra, fator in zip(self.barras, self.fatores_por_barra):
        barra.setValue(int(volume_no_instante * fator))

Ou seja: o QSS cuida do "figurino" (cor, arredondamento, gradiente das barras); o QTimer + o envelope pré-calculado cuidam do "movimento". Essa divisão — estilo estático via QSS, valor dinâmico via Python — é a mesma lógica que vale para qualquer animação em Qt, não só para equalizadores.

09Gerando um executável (Windows e Linux)

A ferramenta mais usada para transformar um projeto PySide6 num executável é o PyInstaller. Ele empacota o interpretador Python, as bibliotecas (incluindo o Qt) e o seu código num único pacote que roda sem precisar de Python instalado na máquina do usuário final.

A regra mais importante

O PyInstaller não faz cross-compilation: ele empacota para o sistema operacional em que ele próprio está rodando. Ou seja, para gerar o .exe do Windows, o comando precisa ser executado dentro de um Windows (ou numa VM/máquina virtual Windows); para gerar o binário Linux, precisa rodar dentro de um Linux. Não existe um único comando que gere os dois de uma vez a partir do mesmo computador.

Passo 1 — instalar o PyInstaller

pip install pyinstaller

Faça isso no mesmo ambiente virtual (venv) onde o PySide6 já está instalado, para o PyInstaller conseguir enxergar a biblioteca.

Passo 2 — gerar o executável

Na pasta do projeto (onde estão main.py, interface_ui.py e, se existir, style.qss):

pyinstaller --noconsole --onefile --name HorizonPlayer main.py
OpçãoPara que serve
--noconsoleNão abre uma janela de terminal preta junto com o player (essencial para um app com interface gráfica). No Windows, o mesmo efeito também pode ser obtido com --windowed.
--onefileEmpacota tudo em um único arquivo executável, mais fácil de distribuir (o custo é abrir um pouco mais devagar, pois ele se descompacta em uma pasta temporária a cada execução).
--name HorizonPlayerDefine o nome do executável gerado (senão usa o nome do script, main).

O resultado aparece em dist/HorizonPlayer (no Linux) ou dist\HorizonPlayer.exe (no Windows).

Passo 3 — incluir arquivos extras (ícone, QSS)

O interface_ui.py é apenas código Python, então ele já vai junto automaticamente — não precisa de tratamento especial. Já arquivos que são lidos em tempo de execução, como style.qss, precisam ser adicionados manualmente com --add-data, porque o PyInstaller só enxerga o que é importado via import:

# Linux/macOS (separador ":")
pyinstaller --noconsole --onefile --name HorizonPlayer \
    --add-data "style.qss:." main.py

# Windows (separador ";")
pyinstaller --noconsole --onefile --name HorizonPlayer ^
    --add-data "style.qss;." main.py

Note o separador diferente entre origem e destino: dois-pontos (:) no Linux/macOS, ponto-e-vírgula (;) no Windows — é o erro mais comum de quem copia um comando de um sistema para o outro.

Ícone do executável

Para definir o ícone do próprio arquivo .exe/binário (o que aparece no explorador de arquivos), use --icon=caminho/para/icone.ico no Windows (precisa ser .ico) ou --icon=caminho/para/icone.png no Linux.

Passo 4 — atenção a "hidden imports" do Qt

Às vezes o PyInstaller não detecta sozinho todos os plugins que o Qt carrega dinamicamente (principalmente plugins de multimídia/codecs de áudio usados pelo QtMultimedia). Se o executável abrir mas a música não tocar, o primeiro passo é rodar sem --onefile primeiro (usando --onedir, que é o padrão) para inspecionar a pasta gerada em dist/, e se necessário forçar a inclusão do módulo:

pyinstaller --noconsole --onefile --name HorizonPlayer \
    --hidden-import PySide6.QtMultimedia main.py

Resumo do fluxo para os dois sistemas

  1. Testar o projeto rodando normalmente (python main.py) em cada sistema antes de empacotar.
  2. Rodar o comando do PyInstaller dentro do Windows → gera o .exe.
  3. Rodar o mesmo comando (ajustando o separador do --add-data) dentro do Linux → gera o binário Linux.
  4. Testar o executável final numa máquina "limpa" (sem Python/PySide6 instalado), que é o teste real de que o empacotamento funcionou.
Alternativa

Existe também o Nuitka, que compila o Python para C e costuma gerar executáveis um pouco mais rápidos e menores que o PyInstaller, com sintaxe parecida (nuitka --onefile --enable-plugin=pyside6 main.py). Vale a pena conhecer, mas para uso didático o PyInstaller é mais simples de explicar e depurar com a turma.
